Use the `profile-optimiser` skill in rewrite mode, on the README surface. Read the README sections of the surface guide first, and say which of the two surfaces this is before writing.

For a project README, the first thirty seconds have to carry: what it does in one plain sentence naming the problem, who it is for and who it is not for, the smallest example that actually runs, and the maintenance status. Philosophy, design principles and comparisons go below that.

For a GitHub profile README, keep it to ten to twenty-five lines of content: what you build and at what depth, three to five repositories worth opening with one line each on why they exist, and how to reach you. Cut badge walls, typing banners, streak widgets, trophy cards and language icon grids.

Leave every code block, command, path, URL, environment variable name, version number, licence text and status badge exactly as supplied. Change prose only.

Replace marketing adjectives (blazing fast, powerful, elegant, seamless, revolutionary) with the measurement, or delete them. Describe what the project does now; what it used to do belongs in a changelog.

Run the gate before returning.
